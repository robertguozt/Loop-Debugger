Loop engineering · Anthropic SDK · Kubernetes

A debugging loop that runs your tests, not its imagination.

loopdbg takes a failing pytest target, spawns an ephemeral pod, reproduces the failure, reads the frames in the traceback, applies one minimal patch, and re-runs the suite. It cannot report a fix it has not watched pass. The loop is forty lines. The harness around it is the part that decides whether any of this works.

Four phases, enforced by evidence

The system prompt splits the work and the agent names its phase before each call. Two rules carry the weight. It may not state a root cause before a failure appears in tool output, and it may not claim success before a passing run appears in tool output. After three patches with no passing run, the loop injects a message telling it to stop editing and widen the search, which is where these agents normally derail.

Architecture

run_debug_cycle posts the transcript to the Messages API, pulls tool_use blocks from the response, runs the matching Python function, and returns tool_result blocks in the next user turn.

Module map
agent.py
loop, phases
tools.py
schemas, impls
executors.py
pods, exec
config.py
tokens, guards
prompts.py
phase contract
cli.py
entry point

The four API calls executors.py makes are create_namespaced_pod, read_namespaced_pod, connect_get_namespaced_pod_exec and delete_namespaced_pod. The RBAC Role grants exactly those and stops.

    Run replay

    A recorded run against examples/broken_project, where calc.stats.median returns the upper middle element of an even-sized sample instead of the mean of the central pair. Two of eight tests fail going in.

    transcript — 8 turns idle
    1. 1reproducecreate_ephemeral_debug_pod image=python:3.11-slim
    2. 2reproducerun_test_suite FAIL — 2 failing, 6 passing
    3. 3localizesearch_codebase /def median/
    4. 4localizeread_file calc/stats.py:20-34
    5. 5patchapply_unified_diff_or_patch calc/stats.py −1/+3
    6. 6verifyrun_test_suite PASS — 8 passed
    7. 7verifycleanup_pod
    8. 8donereport_resolution resolved=true
    0 / 8
    stop_reason: api_error — the model call raised on step 3. The sandbox is torn down in the finally block, partial patches are recorded in the report, and --revert restores every touched file.
    diff — calc/stats.py 
    @@ -25,7 +25,9 @@
     ordered = sorted(values)
     midpoint = len(ordered) // 2
-    return ordered[midpoint]
+    if len(ordered) % 2 == 1:

    root cause, as reported

    median returned ordered[len(ordered) // 2] for every sample size, so an even-sized sample yielded the upper central value instead of the mean of the two central values.

    04

    Cluster

    KubernetesExecutor drives CoreV1Api directly. Commands run through stream(api.connect_get_namespaced_pod_exec, …) with _preload_content=False, the exit status comes off the error channel, and source arrives as a tar stream on the exec stdin.

    k8s/ manifests
    FileObjectsPurpose
    00-namespace.yamlNamespace, 2× ServiceAccountEnforces the restricted Pod Security Standard. Sandbox accounts mount no token.
    10-rbac.yamlRole, RoleBindingPods and pods/exec in one namespace. No list, no watch, no logs.
    20-network-policy.yamlNetworkPolicyDenies sandbox egress except DNS, so code under test cannot phone out.
    30-quota.yamlResourceQuota, LimitRangeCaps pods and CPU against a runaway loop.
    40-runner-job.yamlSecret, Job, PVCRuns the agent itself, with the API key mounted from a Secret.
    k8s/10-rbac.yaml

  # readiness polls use read_namespaced_pod
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["get", "create", "delete"]
  # the client GETs /pods/{name}/exec
  - apiGroups: [""]
    resources: ["pods/exec"]
    verbs: ["get", "create"]
    05

    Install

    The bundled example needs no API key and no cluster. It still drives the real loop, the real tools, and a real sandbox.

    no cluster, no API key 
    git clone https://github.com/robertguozt/Loop-Debugger
cd Loop-Debugger
pip install -e ".[dev]"

python examples/run_example.py            # scripted model
python examples/run_example.py --live      # real model
    against your own repository 
    export ANTHROPIC_API_KEY=sk-ant-...
kubectl apply -f k8s/

loopdbg --repo /path/to/project \
        --target tests/test_thing.py \
        --namespace debug-agent --revert -v
    build and run the runner image 
    docker build -t loopdbg:latest .

docker run --rm \
  -e ANTHROPIC_API_KEY \
  -v "$PWD":/src \
  loopdbg:latest --repo /src --target tests --executor local
    checks that gate CI 
    pytest -q        # 31 tests, no cluster required
mypy             # strict, on loopdbg
ruff check .
ruff format --check .

    --revert restores every file the agent touched and prints the diff it would have left behind. Worth using the first few times you point this at something you care about.

    06

    Guard rails

    An agent that edits files and runs containers needs its blast radius decided in advance, not inferred at runtime.

    Enforced in code and in the manifests
    GuardWhereBehaviour
    Path containmentconfig.resolve_in_repoEvery path resolves against the repository root. Anything outside raises before the read or write.
    Patch validationtools._patchThe snippet must match exactly once, and an edit that breaks ast.parse is rejected rather than written.
    Image allowlistSandboxConfig.validate_imageThe image name arrives from the model, so it checks against a prefix list before any pull.
    Sandbox hardening_pod_manifest, 00-namespaceNo service account token, all capabilities dropped, UID 1000, RuntimeDefault seccomp.
    Egress denial20-network-policySandbox pods reach DNS and nothing else.
    Guaranteed teardownagent.run_debug_cycleThe pod is deleted from a finally block, including when the model call raises.
    Step budgetModelConfig.max_stepsThe loop stops at 30 turns and reports max_steps rather than running on.
