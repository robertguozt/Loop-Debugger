What stops it

  
An agent loop without brakes has one failure mode and it is expensive: it
  decides it is making progress, it is wrong, and it keeps going until the budget is gone. Five brakes run before every
  turn, cheapest first, and the first to trip wins.

  

    
step-cap
A hard ceiling on iterations. The backstop for when every other signal lies.

    
token-budget
Counts both directions and is checked after each turn, so one runaway reply cannot overshoot silently.

    
wall-clock
Bounds real time, which matters when the test suite is the slow part rather than the model.

    
oscillation
Identical test output after a patch means the patch changed nothing that mattered. Three times means the loop is circling.

    
no-progress
Measured against the best result so far, not the previous one — otherwise an agent buys turns by breaking things and un-breaking them.

  






  
Why a checker

  
Green tests are necessary, not sufficient. A debugging agent has cheaper routes to green than fixing
  the defect: special-case the input the test happens to use, weaken an assertion, swallow the exception, skip the test.
  So the test files are read-only at the tool layer — a write to one is rejected with an error written for the model to
  act on — and every green result goes to a checker before it counts. Mechanical checks run first because they are free
  and cannot be argued with. Only then does a second model see the diff and the original failure, told nothing about how
  many attempts it took; a checker that knows the maker is on its last try starts finding reasons to approve. A rejected
  patch is rolled back, because green tests earned dishonestly are worse than red ones — the next turn would build on
  the cheat.






  
Run it locally

  
# the browser demo runs a minimal assert-based runner;
# the CLI runs real pytest against your actual project
git clone https://github.com/robertguozt/Loop-Debugger
cd Loop-Debugger && pip install -e .

export ANTHROPIC_API_KEY=sk-ant-…
loopdbg examples/buggy_project --trace trace.json

# every brake is a flag — the defaults are a starting point, not a recommendation
loopdbg ./myproject -t tests/test_api.py --max-steps 10 --max-tokens 200000 --patience 3

  
Exit code is 0 only when the tests pass and the checker approved the
  change. --trace writes the full run as JSON: every hypothesis, patch signature, token count and verdict.
